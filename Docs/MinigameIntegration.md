# Провода и BP_ComputerCabinet

## Почему игра запускается без перехода на другую карту

Проверены Level Blueprint `L_Test_Wires` и `WBP_WiresMiniGame`. Уровень только создаёт виджет, добавляет его на экран, показывает курсор и включает UI-only input. Проверка трёх пар и событие `Win` находятся в самом виджете.

Поэтому компьютер открывает существующий виджет в текущей комнате. Игрок и уровень не пересоздаются, позицию персонажа не нужно сохранять и восстанавливать через переход карты. `/Game/Minigames/Wires/L_Test_Wires` остаётся самостоятельным стендом разработчика; обе существующие ссылки/файла тестовой карты не изменены.

## Что открыть в редакторе

| Ресурс | Где лежит | Что здесь находится |
|---|---|---|
| `BP_ComputerCabinet` | `/Game/NENS/Environment/Interior/Blueprints` | Вход в мини-игру и реакция компьютера на завершение |
| `WBP_WiresMiniGame` | `/Game/Minigames/Wires` | Внешний вид, кнопки, `CheckPair`, переменные `SelectedLeft`/`ConnectedCount`, `Win` |
| `L_Test_Wires` | `/Game/Minigames/Wires` | Прежний отдельный запуск для проверки проводов |

В `BP_ComputerCabinet → Components` добавлен компонент **Minigame**, класс C++ `MinigameComponent`. Его `Widget Class` назначен на существующий `WBP_WiresMiniGame`.

`Event Interact` вызывает ноду `Open Minigame`:

```text
Target = Self
Interactor = вход из Event Interact
```

Ниже в EventGraph:

```text
On Minigame Closed (Minigame)
    → Branch Completed
        True → SetAwarenessVisible(false)
             → Widget_InteractionPrompt.SetHiddenInGame(true)
             → Ring_Visual.SetHiddenInGame(true)
```

При выходе без победы Completed=false: компьютер остаётся доступен. После победы исчезают только индикаторы, сам компьютер остаётся видимым. Общая проверка доступности в `BPC_Interaction` также исключает завершённый компьютер из выбора цели.

## Минимальные изменения игры коллеги

Родителем `WBP_WiresMiniGame` стал C++ `MinigameWidget`. В нём предусмотрены две ноды связи с общей системой:

- **Report Success** — сообщить, что задача успешно выполнена.
- **Request Close** — закрыть именно эту попытку и вернуть управление.

В существующий `Win` после текста «Успех!» добавлен `Report Success`. Сохранена прежняя задержка в одну секунду и последующий вызов `CloseMiniGame`.

Внутри функции `CloseMiniGame` вход выполнения теперь идёт в `Request Close`. Старые ноды переключения ввода/удаления окна остались отключёнными: это теперь делает общий сеанс. Кнопка «Закрыть» по-прежнему вызывает `CloseMiniGame`.

`CheckPair`, правила соответствия трёх пар, кнопки, изображения проводов и счётчики сохранены из обновления коллеги `96dcaa7`. При объединении сохранены также его фон `T_Wires_Bg_png`, текстура `T_Wire_png` и оформление виджета. Поверх этой версии восстановлены родитель `MinigameWidget` и вызовы `Report Success`/`Request Close`. Разработчик может продолжать менять игру в Blueprint. Условие победы должно вызывать `Win`/`Report Success`, а все выходы — `CloseMiniGame`/`Request Close`.

## Поведение попытки

1. E в допустимой зоне открывает игру; курсор виден, персонаж остановлен, игровые команды заблокированы.
2. Escape и исходная кнопка «Закрыть» завершают текущую попытку.
3. После отмены следующий вход создаёт **новый** виджет: соединения и выбор разъёма сбрасываются. Это выбранное пользователем поведение.
4. После трёх правильных пар успех сразу записывается в компонент компьютера. Даже Escape во время секундного сообщения об успехе не отменяет победу.
5. После закрытия успешной попытки подсказки скрываются, повторный запуск этого компьютера запрещён.
6. У разных экземпляров компьютера независимый флаг успеха. SaveGame пока нет: при пересоздании Actor/новом Play результат сбрасывается.

У компонента есть события **On Succeeded** и **On Minigame Closed(Completed)**. Первое подходит для будущего игрового флага/разблокировки двери; второе — для реакции объекта после удаления окна. Логика дверей и инвентаря в этой задаче не добавлялась.

## Общий ввод с осмотром шкафа

Добавлен `InteractionSessionSubsystem` — один владелец активного окна для локального игрока. Он используется и осмотром, и мини-играми:

```text
Шкаф → InspectionSubsystem → InteractionSessionSubsystem
Компьютер → MinigameComponent → InteractionSessionSubsystem
```

Он отвечает за одно окно одновременно, UI-only input, фокус, остановку движения, показ курсора и восстановление управления. `InspectionSubsystem` сохранил своё API и работу с предметами, но переключение ввода передаёт общему механизму.

При закрытии отменяются анимации/отложенные действия этого окна. Кроме того, запрос закрытия/победы проверяет, что пришёл от текущего виджета. Поэтому задержка из старой попытки не может закрыть другую мини-игру или вернуть игровой ввод поверх нового окна.

Если владелец активной игры уничтожен, общий сеанс закрывается и возвращает управление.

## Исходники

В `Source/NENS_Project/Public` и `Private`:

- `InteractionSessionSubsystem.h/.cpp` — общее владение окном и вводом.
- `MinigameComponent.h/.cpp` — настройки, активная попытка и успех конкретного Actor.
- `MinigameWidget.h/.cpp` — две ноды связи, Escape и безопасное закрытие; поддерживает запуск виджета напрямую из старого тестового уровня.
- `InspectionSubsystem.h/.cpp` — прежний координатор осмотра, использующий общий сеанс.
- `InspectionBlueprintLibrary.h/.cpp` — ноды открытия и проверки доступности; теперь учитывают и компонент мини-игры.

В `Source/NENSInspectionEditor` находятся только настройка и тесты. `Tools/configure_wires_minigame.py` — служебная первоначальная интеграция двух Blueprint, а не обязательный шаг перед каждым Play. Не запускай его для обычного редактирования игры.

## Как подключить следующую мини-игру

Если игра уже целиком реализована в UMG:

1. Сделать её WBP потомком `MinigameWidget`.
2. При фактической победе вызвать `Report Success`; для выхода использовать `Request Close`.
3. Добавить объекту компонент `MinigameComponent`, назначить Widget Class.
4. Из `Event Interact` вызвать `Open Minigame(Self, Interactor)`.
5. Подключить `On Minigame Closed`: при Completed=true скрыть индикаторы, как у компьютера.

Новые игры не должны сами вызывать `SetInputMode_GameOnly` при закрытии встроенной попытки: вводом владеет общий сеанс. Если игра действительно зависит от 3D-акторов/камеры/физики отдельного уровня, её сначала нужно разобрать отдельно; такой перенос не сводится к двум нодам виджета.

## Проверки

Автотесты:

- `NENS.Interaction.Minigame.ComputerWires` — вход через существующий BPC, тот же мир/персонаж/позиция, неправильная и правильная пара, Escape после клика на фон, кнопка закрытия, новая попытка без старых соединений, исключение одновременных окон, настоящие клики по трём парам, победа, чужая старая задержка, независимый второй компьютер, скрытие индикаторов при повторных пересечениях зон и закрытие при уничтожении владельца.
- `NENS.Interaction.Minigame.OriginalTestLevel` — прежний тестовый уровень самостоятельно создаёт виджет, игру можно выиграть, секундная задержка корректно закрывает её.
- Все четыре прежних теста `NENS.Inspection` — регрессия шкафа и прогресса на общем вводе.
